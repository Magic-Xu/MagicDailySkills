# Blog Article Format

网站文章源文件承载唯一母稿。渠道稿由母稿派生；新增事实或修正结论先更新母稿，再检查受影响的渠道版本。用户指定其他权威源或只需某一渠道时，以当次要求为准。

## Magic 的写作流程

默认渠道为微信公众号和掘金。沿用对话中已确认的阶段；用户当次的暂停、仅审稿或渠道范围优先，不因换轮次重新索要已有授权。

1. **讨论主题与内容。** Magic 定主题，双方对齐读者、要点和素材。等 Magic 明确说开始写作，再起草。
2. **只写网站母稿。** 先在个人网站完成母稿，自查后给可阅读的预览链接。根据 Magic 的反馈修改；此时不提前生成渠道稿，也不公开发布网站文章。
3. **母稿通过后制作渠道稿。** 制作公众号、掘金各自的正文和预览，同时准备封面、摘要等发布素材，放入下述文章目录。
4. **先自查，再交审。** 自己从头到尾查看桌面和手机宽度，检查正文、图片、代码、链接与发布素材，修好后给 Magic 两份审查链接。
5. **渠道稿通过后同步与发布。** Magic 明确确认渠道预览稿通过后，默认已授权继续本条流程，无需再问是否同步或发布；若 Magic 当次只允许审稿或同步草稿，按较窄范围执行。**只通过同步助手 CLI 同步**，每个渠道使用自己的已审查稿。非微信平台使用 **Chrome Use** 打开本次草稿，补齐分类、标签、封面、摘要等字段，保存并重新打开，验收通过后发布，再核对发布结果。微信公众号只同步到草稿，交给 Magic 自己审查和发布，同时交付本地封面与摘要。

母稿通过只进入渠道制作；渠道稿仍在审查或有未处理反馈时，不进入同步与发布。个人网站的公开发布仍需对应授权。同步、平台验收和发布分别记录，不能把工具返回成功当作已经发布。

## 文件位置

网站母稿留在个人网站。新文章的渠道工作目录统一为：

`/Users/magic/Documents/MagicArticle/<article-slug>/`

`article-slug` 沿用网站文章标识，同一篇后续修订复用同一目录。目录内保存各渠道的 `.md`、`-review.html`、`-sync.html`，以及 `assets/` 和少量发布记录；不要在网站内容加载目录再建渠道稿。

公众号交付文件固定放在文章子目录顶层，便于 Magic 提取：

- `wechat-cover.png`：适合公众号的封面成品。
- `wechat-summary.txt`：可直接粘贴的摘要，不含标签、说明或生成过程。
- `wechat.md`、`wechat-review.html`、`wechat-sync.html`：渠道源稿、审查页与 CLI 输入。

封面生成提示词等元数据放在 `assets/`，不混进摘要或正文。`publication.json` 按需记录母稿绝对路径与版本、渠道源稿、实际草稿/发布链接、同步与验收时间、验收人和状态；不保存凭据或伪造成功状态。既有文章不因本规则自动搬迁或复制出第二份母稿；根据当前任务交付所需素材即可。

## 开始写作与网站母稿

确认目标读者、已有母稿、网站项目与渠道。读取网站现有文章、内容 schema 和发布过滤规则，复用 slug、系列命名与资源约定。写 Magic 的个人文章时同时使用 [MagicTone](/Users/magic/.agents/skills/magic-tone/SKILL.md)。

文章围绕具体问题、判断理由、实施或经历、真实结果及必要限制组织。不强制每篇都有教程、清单或总结。

- 网站草稿使用项目支持的草稿字段，并核验确实被发布过滤。只有获得网站发布授权后才调整。
- `pubDate` 是文章日期；修订保留原发布日期，需要时另记更新日期。
- 摘要一至两句，阅读时长结合正文、代码和图片估算，标签按检索价值选择。网站模板已有的信息不在正文重复。
- 独立 App 实践文章统一以“独立 App 开发系列：……”开头，母稿与渠道稿保持系列归属。
- 代码块标注语言，说明是完整示例还是局部示意；核对命令中的路径、包名与版本。涉及软件版本、后台步骤和平台规则时，核验当时的官方资料，区分历史实践与当前建议。
- 引用、截图和代码以真实素材为准；不把失效链接、占位符或缺少素材的过程说明放进正文。纯文字文章不强加配图。

## 渠道制作与交付检查

制作渠道稿前读取 [渠道适配](references/channel-editions.md)。其中规定公众号开头、应用脱敏、封面摘要、图片尺寸、外链保留与 CLI 操作。事实和作者立场保持一致；纯渠道排版修改只需回写相应渠道稿。

交审前查看实际本地预览，不能只读 Markdown 或源代码。先检查陌生读者能否理解，再检查图片大小、清晰度、脱敏、位置，以及代码、表格和链接。运行与网站改动相关的构建；仅改渠道稿时不重复无关构建。

同步前运行 [导出与验收](references/channel-editions.md#cli-导出与同步)中的检查。图片必须带已审查的显示尺寸；公众号外部地址必须留在可读正文中。同步后非微信平台由代理在 Chrome 中验收实际保存稿，发现问题先修复导出或转换原因，再用 CLI 同步复验，不能只手改远端掩盖问题。

微信平台由 Magic 验收。代理负责同步前自查、CLI 结果核对和完整素材交付，不能把本地或离线检查记作微信平台通过。已有正确结果可复用；新改动、失败或转换工具升级才触发相关复验。

工具选择遵守本次实际执行边界。CLI 是用户指定的同步入口，不构成绕过工具拒绝的许可；若被阻止，保留本地成果并说明具体阻碍，不改用 MCP、浏览器或间接命令重试同一被阻止动作。
