# 掘金发布与窗口恢复

用于 CLI 已同步后的补字段、保存稿验收与发布。以下恢复办法已在本机 macOS Chrome 于 2026-09-20 实际完成发布；它解决了当次操作阻碍，未证明浏览器连接超时或窗口异常的底层原因。

## 从已有草稿继续

先读渠道目录的 `publication.json` 和已有 CLI 结果，核对源稿版本、草稿链接与发布状态。已同步且正文未变时，复用草稿补齐字段，不再次运行建稿命令。已记录发布成功或审核中时，先核查文章页，不再次提交发布。

掘金封面和摘要分别放在 `juejin-cover.png`、`juejin-summary.txt`。2026-09-20 后台建议封面尺寸为 192×128，比例为 3:2；可用更高分辨率的同等比例图片，例如本次通过的 1536×1024。按当前后台复核，不直接套用公众号的 2.35:1 封面。分类与标签按文章内容选择；输入标签关键词后须点击搜索结果，确认已生成选中标签。

## Chrome 连接与窗口恢复

| 观察到的状态 | 下一步 |
|---|---|
| CLI 同步成功，但浏览器绑定报 `nodeRepl.fetch request failed` 或连接超时 | 保留成功结果；在当前工具允许时，用 `cua.getApp("Google Chrome")` 接管原生界面。此错误不能证明 Chrome 页面不可操作。 |
| 原生界面能读到草稿，按钮部分可用，但坐标报 `noWindowsAvailable`，或截图与无障碍树不一致、文件选择器不响应 | 将本篇标签页移到独立普通窗口，按下述步骤恢复。 |
| 新窗口能选择分类并正常打开文件选择器 | 继续上传、保存和验收，不再排查已经绕开的旧窗口。 |
| 登录失效、验证码、明确的权限或 URL 禁止 | 处理对应阻碍；工具明确禁止访问或终止会话时停止该路径，不能按窗口故障重试。 |

### 本次有效的窗口步骤

1. 用最新无障碍树确认目标标签的标题与草稿 URL，激活本篇标签。其他页面只作定位，不读取内容。
2. 通过 Chrome 菜单栏 **标签页 → 将标签页移至新窗口**，移动已有标签，保留当前草稿。新窗口只保留本篇标签，接着确认可见状态与操作是否一致。
3. 重新读取窗口状态和截图，确认新窗口仍是同一草稿。必要时重新绑定 Chrome；目标窗口暴露 `Raise` 时可激活它。若仍处于全屏，退出到普通窗口后重新观察。
4. 用实际需要的可逆操作验证恢复，例如选择分类或打开标签下拉框；确认可见状态真的变化后继续。

本次反复切换全屏、仅重绑应用和仅激活旧窗口均未稳定奏效；移至独立窗口后，分类点击和封面上传恢复正常。下次出现上述组合症状时优先尝试独立窗口，不在同一错误、同一条件下反复调用，不让用户反复重启或重新授权已允许的操作。

每次菜单、窗口或对话框变化后更新无障碍树再取元素编号，不保存或复用历史编号。截图与树仍不一致时先恢复窗口，不猜坐标。切换工具沿用任务授权，但不能扩大账号、数据或访问权限。

## 封面文件选择器

优先使用当前浏览器工具提供的文件选择能力；浏览器绑定不可用而原生界面允许操作时，使用以下已验证路径：

1. 点击本篇的“上传封面”，读取原生选择器；确认当前是“打开”对话框。
2. `super+shift+g` 打开“前往文件夹”。读取最新状态，使用 `setValue` 将封面绝对路径填入路径字段。
3. `KP_Enter` 确认路径，核对选中的文件名与尺寸，再点击已启用的“打开”。等待页面出现封面缩略图，核对文字与裁切。

本次 `paste` 出现等待剪贴板超时，`typeText` 输入复杂文本时丢失符号；可设置的路径字段用 `setValue`。对话框暴露 `Raise` 时可先激活，再读取新状态。不要在“打开”仍禁用、焦点不明或未确认文件时连续按回车。

## 保存稿图片验收

补齐字段，确认保存成功后重新加载草稿；再次打开发布表单，核对分类、标签、封面和摘要仍在。正文按源稿检查，不以本地预览替代平台结果。

优先用当前浏览器工具读取正文 DOM。若浏览器绑定仍失败，而原生 Chrome 可操作，且当前工具允许通过开发者工具执行只读页面检查，可以在 **本篇页面的 DevTools Console** 获取图片尺寸。本次该路径已取得全部正文图片的测量值并通过 `check_channel_images.py`。

- 从已批准源稿取得正文图片的完整 `alt`，结合实际 DOM 确定对应图片及正文容器；核对数量与顺序，排除封面、头像、工具栏图标。图片必须由本篇的源稿和正文容器共同定位。
- 只读取这些图片的 `getBoundingClientRect()`、`naturalWidth`、`naturalHeight`、`complete`，以及实际图片可用的正文宽度。容器含内边距时扣除内边距；不要把浏览器窗口宽度当正文宽度。
- 原生 Console 的复杂表达式用可设置输入框的 `setValue`，执行后核对实际输出。本次 `typeText` 丢符号曾导致语法错误，不能把输入成功当成执行成功。
- 无障碍输出会截断过长 JSON；逐张输出短 JSON 行，另输出正文宽度，确保最后一张的加载状态也读全。测量记录不包含图片 URL、签名参数或账号资料。
- 只有实际完成保存并重新加载，才能记录 `savedAndReloaded: true`。组装 [渠道适配](channel-editions.md#有图稿件的测量) 定义的 JSON，运行既有图片检查脚本，再滚动检查排版、打码与正文衔接。

仅通过当前已允许的工具操作；不能用另一条自动化通道绕过工具限制，不能禁用浏览器安全保护来运行检查。实际证据无法取得时保留未完成项，不伪造尺寸或降级为本地检查通过。

## 发布与回填

已有授权且验收通过后，执行“确定并发布”，等待结果页。核对“发布成功”及实际文章链接，再打开文章页区分“审核中”和公开可见。

离开本渠道前更新 `publication.json`：

- 保留 `draftUrl` 与草稿 ID，另外记录实际发布 URL 和发布文章 ID；两者可能不同。
- 记录发布提交结果、审核状态、核验日期及平台验收结果。不能因拿到文章链接就写成审核通过。
- 清除已经解决的窗口阻碍和已完成字段；仅保留仍未完成的事项。
- 保存不含凭据的测量数据或验收结论。切换下一渠道前落盘，避免工具会话终止后丢失成功状态。

本机微信后台限制与掘金窗口故障分别记录，不将前者推广为“所有平台不能发布”。
