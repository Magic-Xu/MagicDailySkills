# 产物边界检查

完成常规验证、即将交付持久化产物时使用；纯问答或没有待审产物时不运行。目标是让读者获得完成当前任务所需的有效信息，检查深度随产物和风险变化。

## 默认检查

并入最终 diff 或产物审查，复用本任务已明确的需求、读者、基线和规则，不重复读取或另写审查报告。

1. 确定本任务的有效需求与改动范围，区分用户原有改动。代码、UI、配置和说明以真实终态为准；提交、PR、发布说明以正确的比较基线为准；ADR、复盘等过程型产物按其用途保留必要过程。
2. 判断新增或修改的内容是否服务目标读者的当前任务，是否真实，是否放在读者需要的位置。删除只来自否决方案、中间尝试、Agent 自检或临时误解的内容。
3. 规则和测试须表达有独立证据支持、可验证且持续成立的约束。历史错误只能提示审查，不能单独作为新增规则或删除真实回归测试的依据。
4. 只在已有编辑授权内修复本任务引入、可逆且结论明确的内容，复查受影响部分；只读审查给出位置与最小建议。若歧义会改变产品语义或操作需要新的授权，询问并继续不受影响的检查。

安全、兼容性、迁移要求和必要的 workaround 按真实约束判断；不要凭否定措辞、关键词或正则命中删除内容。本检查不替代功能、视觉、安全或领域验证。

## 需要深入检查时

新建或大幅重写面向用户的文档、需求发生实质变更、发布内容跨多个基线，或默认检查发现读者用途不清时，按问题读取 [深入审查指引](references/detailed-review.md) 的相关部分。

## 完成

检查通过即可交付。存在实质修复或待决定歧义时简述；没有问题时无需单独展开质检过程。不递归调用本技能；若同一问题两轮修复后仍无法解决，明确说明阻碍。
