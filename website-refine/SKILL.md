# 网站精修

让已有网站形成明确、合适的视觉表达，并达到经过实际体验验证的完成度。把“不满意”转成具体差距、设计决策与可检查的改进。

## 确定范围与方向

- 先读取当前网站、项目规则、真实内容与已有设计约束，明确面向谁、主要传达什么、希望访客完成什么。保留有效品牌特征、功能与用户已有改动。
- 用户要求“分析”“评审”时保持只读；要求精修时推进到实现和验证。已有网站是主要入口；从零建站任务可在形成首版后使用本流程精修。
- 从当前任务、项目材料与用户提供的参考中提取审美偏好。普通细节自主决定；存在会明显改变品牌、内容含义或工作范围的分歧时，用少量参考或关键页面样稿呈现选项与推荐，先讨论受影响的方向。
- 指定框架、设计系统、内容事实、数据含义和权限边界持续有效。不要以视觉优化为由重写无关架构、虚构业务证据或发布网站。

## 查看现状，建立比较基线

运行或打开真实页面，检查代表性页面、桌面与移动端，以及主要操作路径。记录本次页面、视口和关键状态，保存并查看修改前截图；动效和操作必须实际体验，不能由静态截图推断。

按对访客理解、品牌表达和操作的影响排列问题。每个主要问题应说明：在哪里、观察到了什么、为什么影响目标、准备怎样改善。优先解决影响全局的结构与层级，再处理局部细节。

缺少代码权限时，可先完成可访问页面的诊断；缺少运行或浏览器能力时，说明未验证范围，继续能够完成的工作，不把代码审阅或生成的效果图当作真实视觉验收。

## 用参考校准，而非套用风格

优先查看用户提供的参考；需要补充时，从与受众、内容和用途相近的优秀作品中选取少量案例。可以从下列来源寻找：

- [Awwwards](https://www.awwwards.com/)：参考设计、可用性、创意与内容的综合完成度；[评估标准](https://www.awwwards.com/about-evaluation/)。
- [Webby Awards](https://www.webbyawards.com/)：关注内容、导航、功能、交互与整体体验；[评审标准](https://www.webbyawards.com/judging-criteria/)。
- [FWA](https://thefwa.com/)：参考数字体验的原创表达与技术创意；[官方介绍](https://thefwa.com/FWA25/25.html)。

查看案例的真实页面与相关交互，为每个采用的参考说明“借鉴什么、为何适用、如何转化为当前网站的表达”。声称获奖时核验奖项来源；无法访问实站时说明观察限制。奖项提供参照，不是固定风格或获奖承诺。

形成简短设计方向：内容重点、视觉气质、字体与配色角色、版面逻辑、最有辨识度的表达，以及需要保留的部分。审视这些选择是否来自当前内容；采用参考的设计原则，不复制其品牌、文案或标志性构图。

## 实施与复验

按最高价值问题实施，必要时调整相关区块的结构、文案呈现和素材。保持页面与组件的整体一致性，覆盖受影响的内页、下半页及关键状态。主要图像、产品界面、图表和真实内容均属于设计材料；素材缺口应明确，不用装饰掩盖。

每轮修改后打开实际页面，查看截图并操作受影响的流程。使用相同视口和状态进行前后比较，区分修复问题、改善表达与纯风格替换。继续处理明确、值得解决的问题，避免只在代码中反复微调。

| 维度 | 检查重点 |
| --- | --- |
| 排版 | 字体角色、字重、字号、行长、行距与断行是否支持内容；中外文混排是否协调 |
| 留白 | 对齐和间距是否表达内容关系，疏密与阅读节奏是否合适 |
| 视觉层级 | 第一眼重点、阅读顺序与主要行动是否清楚，次要内容是否喧宾夺主 |
| 色彩 | 品牌表达、主次与状态色是否一致，文字和操作是否易于辨认 |
| 动效 | 是否帮助理解、反馈或衔接；时序自然，不拖延操作；尊重减少动态效果的偏好 |
| 微交互 | 相关控件的悬停、焦点、按下、加载、成功、错误和空状态是否清楚、连贯 |
| 响应式 | 代表性窄屏、中间宽度与桌面下内容是否合理重排，阅读、触控和导航是否可用 |
| 原创性 | 表达是否来自品牌与内容，是否有明确而适当的辨识度，装饰是否服务整体方向 |

按实际改动检查功能、键盘操作、语义、加载体验和性能回归；执行项目要求的构建与检查。自动检测补充实际视觉和交互检查，不能代替它们。动效较多或关键流程较长时，用录屏复查连续体验。

## 完成与交付

完成前整体查看一次：

- 已识别的明显问题已解决，主要页面与关键操作经过验证，视觉方向与细节保持一致。
- 没有因本次修改引入功能、可访问性、响应式或加载体验的明显退化。
- 在本次目标与范围内，仍有具体、可论证的高价值改进时继续实施。若继续推进依赖审美选择、缺失素材、权限或扩大范围，说明差距与选项，不宣称已达成。

交付可访问的预览或可运行产物、少量关键前后截图，以及实际改进、检查范围和未解决限制。动效与交互用可操作预览或录屏呈现。用证据支持完成度，不把自评分数当成用户满意或获奖资格。

技能正文维护通用方法；个性偏好与具体任务材料保留在对应项目。不强依赖某一框架、浏览器品牌或其他本地 Skill。
