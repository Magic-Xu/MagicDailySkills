# 小红书探索

把分散的经历、追问和经验整理成用户能理解、能比较、能继续验证的信息。保留结论适用的条件，明确哪些是作者自述、哪些已经核实、哪些仍是推断。

## 明确这次要探索什么

先从会话和用户指定的资料中提取目标、重要偏好、时间与地域、已有方案和希望得到的结果。已知信息直接复用；只有缺失信息会实质改变搜索方向时才询问，同时继续不依赖答案的工作。未确认的个人条件不要当作事实。

把宽泛话题拆成能影响判断的问题。例如“适合住一个月”还涉及短租期限、日常吃饭、工作环境、交通与社交；“想做一个产品”还涉及谁遇到什么问题、发生频率、现有替代办法和解决成本。不要擅自把开放探索收窄成购买推荐或产品立项。

按任务选择关注点，不必覆盖所有类别：

| 探索目的 | 优先寻找的证据 |
| --- | --- |
| 旅居、生活选址 | 普通日子的实际体验、具体区域与楼栋、居住期限、配套、交通、总费用及限制条件 |
| 消费和服务选择 | 使用一段时间后的反馈、失败和退换原因、适用人群、售后与额外成本 |
| 社群和活动 | 最近实际举办或参与的记录、地点、频率、参与方式、交流内容；宣传定位不能证明当前活跃程度 |
| 办事经验 | 办理时间、城市与个人适用条件、材料、步骤和卡点；正式要求另核实 |
| 产品需求 | 触发场景、反复出现的问题、现有解决办法、已经付出的时间或金钱；“想要”“求一个”不直接证明付费意愿 |
| 内容选题 | 读者追问、信息缺口、争议与误解；区分讨论热度和事实依据，保留素材出处 |

## 访问小红书

用户指定浏览器、账号或页面时沿用该入口；已登录的浏览器可直接用于搜索和阅读。未指定时，选择当前可用且能完成阅读与核验的连接器、CLI 或浏览器工具。先读取所用工具的操作说明，不把固定选择器、旧页面索引或某次会话的连接方式写成通用前提。

登录失效、验证拦截或工具故障时，先按当前工具文档作合理恢复；仍不可用，就保留已读证据并说明缺口。若使用公开网页补充，说明实际覆盖范围，不能把搜索摘要说成已读笔记全文。遵守访问控制，不用提取 Cookie、登录令牌或逆向私有接口来绕过限制。

探索默认包含搜索和读取。发表评论、发送私信、联系商家、发布笔记、加入群组及预订等动作需有相应的用户授权；需要询价时，可以先提供可复制的询问文字。搜索词仅包含完成问题所需的信息，不把个人资料整段发送到外部平台。

## 搜索与深读

从少量不同角度的查询开始，随着证据调整：

- **目标词与具体场景**：地点／对象＋用户要完成的事情。
- **现实约束**：时间、期限、使用方式、预算条件、交通或适用资格。
- **体验与反例**：长期使用、实住、退货、踩坑、退出、失败原因等。
- **新发现的实体**：对反复出现的店名、社区、产品、区域或作者继续查证。

平台提供排序或筛选时，按问题结合近期信息和有细节的经历。热度帮助发现线索，不能替代相关性或可信度。不要只围绕最初看中的选项搜索；保留有竞争力的替代项，并主动查找会推翻推荐的证据。

进入关键笔记，读正文、承载事实的图片或视频内容，以及与目标相关的评论和回复。重点看追问后才出现的价格条件、最低期限、额外费用、作者更正、实际地址和近期状态。作者的回复与其他评论者的猜测分别记录。

搜索结果卡片、推荐词和平台 AI 摘要只作为线索，重要事实回到原始内容核对。评论没读到、图片看不清、视频无法完整查看时，不补写其中的信息。浏览器切换或页面变化后，以新状态确认位置再操作。

## 把经历整理成证据

对影响结论的材料，保留足够的定位信息：作者、标题、实际取得的链接、发布或编辑时间（若可见）、体验发生时间、关键条件与结论。检索日期与体验日期分开，重新看到旧帖不代表内容已更新。资料较多或需要持续研究时用简表暂存，简单问题不必额外建库。

判断证据时注意：

- **来源身份**：住客／消费者自述、经营账号、其他评论者、转载或官方资料。身份不明就保留不明状态。
- **独立性**：同一作者、同一商家素材或重复转载不算多个独立证据。精选帖子和评论不能代表总体比例。
- **适用条件**：日期、地区、房型／型号、最低期限、资格、收费包含项是否一致。历史低价、限时活动和展示价不能直接当作当前可成交价格。
- **对象是否相同**：区域、楼盘、具体经营者与门店分别核对；相似名字或邻近位置不能证明是同一家，也不能推出实际步行时间。
- **冲突是否可解释**：先检查时间、版本、地点和使用条件。解释不了就并列呈现分歧，并说明它会影响什么决定。

将用户偏好转换为可观察的条件。例如希望找到合适的交流对象，就看活动主题、实际参与者分享和互动方式；不能用职业标签、收入、学历或营销定位代替社群体验。

必要时用官方页面、地图、商家公开资料或其他独立来源核对会改变决定的事实。医疗、法律、社保、财务等事项以权威来源核实适用规则，个人经验用于发现问题和准备询问。用户限定只查小红书时保留这个范围，把尚未权威核实的部分明确列出。

## 何时继续、何时交付

围绕尚未解决、且可能改变结论的缺口继续搜。主要选项已有相关证据、关键条件与反面体验已检查，新增结果只重复已有信息时即可收束；不要为凑固定帖子数机械浏览。没有找到满足条件的方案，也是一种有效结果。

来源不足以支持结论时，给出目前能成立的判断和下一步验证方式。不要承诺“全网穷尽”，也不因用户希望得到明确答案而把线索写成确认结果。

## 交付方式

按用户的任务选择篇幅和载体，通常先给最有用的结论，再提供比较、证据和下一步：

- 选择型任务说明推荐顺序、适合条件、取舍，以及什么情况应改选。
- 学习或发现型任务归纳主要现象、差异和仍需研究的问题，不强行给唯一答案。
- 产品研究区分观察到的问题、对需求的解释和待验证的产品假设，不能把未经验证的推断写成需求规格。
- 关键事实附就近来源链接；小红书链接可能需要登录，保留作者和标题便于重新定位。只使用实际取得的链接。
- 待确认项紧贴对应建议，写清确认内容和它会怎样改变决定。需要行动时，可提供试用／试住计划、访谈问题或询价模板。

篇幅较长时提供可独立阅读的摘要。比较适合用表格；关系、位置或步骤确实难以用文字看清时再配图。用户要求文档或知识库沉淀时，使用对应载体的工具与规则，并核对实际呈现；保存的内容围绕有效结论、来源、日期和持续约束，避免写入工具日志、账号凭据及无关个人信息。

交付前检查：结论是否回答了用户的实际问题，限制条件是否齐全，个人自述与已核实事实是否区分，主要反例是否处理，链接是否对应所述材料，预算与比较是否采用同一口径，以及下一步是否可执行。检查深度随任务风险调整，不把探索输出包装成已成交、已预约或已验证的现实结果。
