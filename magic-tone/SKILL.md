# MagicTone

帮助 Magic / MagicXu 写出有个人判断、事实依据，读起来像同行交流的文章。负责表达风格与默认文章开头；具体内容按本篇目的展开，署名按实际渠道使用。用户当次指定的体裁与格式优先。

## 表达底色

- 从具体事实出发。写清发生了什么、作者做了什么、为什么这样选；分清亲历、外部知识与推断，不编造经历、成果或情绪的来由，也不把情绪强度写得超过素材。
- 有判断，也有理由。支撑判断的事实讲具体，适用条件紧挨结论。允许结果普通、数据不好看或事情尚未完成，不包装成功叙事。
- 用平常会说的话表达。像同行认真交流一件做过的事，不摆导师姿态，不为了显得专业堆术语，也不为了显得随意添加口头禅。
- 保留作者的情绪和吐槽。烦、嫌麻烦、失望、觉得值不值，都是理解选择的内容，不要在整理时一律磨成中性的说明书。把情绪放在触发它的具体事实旁，写出作者在意什么、为什么不想继续或愿意花钱；不要求每段都有情绪，也不为了“人味”表演粗口或夸张。
- 尊重读者的理解过程。保留说明来由、前提和取舍所需的信息，重要处讲透，次要处收短。默认读者具备正常的阅读和界面操作能力，省去“点击图片查看大图”等显而易见的指示。

## 文章开头

先交代作者在做什么、遇到了什么问题，以及为什么需要讨论它。背景以信息够用为准，不编场景，不先铺行业大势。短分享和吐槽可以直接进入事情本身。

按文章内容和阅读需要决定是否增加导读。教程、长篇分析等需要时，可补充适用读者、文章收获或一句话总结；这些项独立选用，不要求三项齐全，不为凑格式编造收获。用户指定导读时按其要求安排。

标题下不默认再加一段内容简介。网站摘要等元数据按渠道需要保留，不自动当作可见开头。

## 句子与段落

- 标题直接交代方法、判断或要解决的问题，让读者知道这一节有什么用。少用“后来，我在……”“我又……”把时间顺序当标题；需要交代先后时放进正文。正文回应标题的承诺，不把所有信息都挤在标题里。
- 分清平台要求、操作步骤与作者的额外选择。发布前必须填写的资料，就写清要填什么、在哪里填、填完才能做什么；不要写成“我还填了……”来暗示作者另外做了什么。第一人称用于有价值的亲历、取舍和结果，不给每个标准步骤都加“我”。
- 方法要能照着做。涉及找入口、找服务或填资料时，给出必要的入口、搜索词、填写内容和结果判断，不只叙述作者做过这件事。按本篇实际采用的方案交代分工，不把通用流程中的每项工作都写成作者或读者必须亲自完成。
- 句子把谁做了什么说清楚。抽象名词能换成具体动作时就换；动作多时交代先后，原因复杂时先讲主要原因，再补条件。
- 一段围绕一个意思展开，后句解释、举例或推进。保留必要的指代、因果和转折，长短以读一遍能明白为准，不人为制造碎句和停顿。
- 检查“从……到……再到……”“也说清……”“本文将……”一类内容预告，以及泛泛的评价、升华和段间过渡。先判断它有没有新增信息：只有目录作用就删；承载事实就直接讲事实。不要仅换一组近义词保留原来的空壳。真实的过程和顺序仍可正常说明。
- 连接词、冒号、引号、排比和清单按用途使用。步骤和并列信息可以列出；不要用禁词数量、标点禁令或固定段落长度代替阅读判断。
- 写到意思完整即可。结尾可以收束作者的选择或判断，不强加鼓励、升华，也不把前文再复述一遍。

## 公开表达与配图

- 购买服务的交易平台默认用化名，例如“某鱼”；不附商家、联系方式或交易入口来引流。理解技术步骤必需的产品与平台名称正常保留，不把化名规则扩大到所有工具。
- 个人具体日期、账号与其他可识别信息，只保留读者理解方法或结论必需的部分。不要因为查到了准确时间就写进正文；政策生效日期、规则核验日期等有解释作用的信息仍可保留。
- 需要截图支撑的结果，把可用的真实截图放在对应结论旁。核对过邮件不等于已经交付邮件配图，也不能靠补一个精确日期代替证据。
- 公开截图检查整张画面，包括系统状态栏里的 VPN、通知与设备状态，浏览器标签、书签、地址栏，以及个人账号、应用身份和无关日期。优先裁去无关区域，必要处遮挡；保留原图和能支持正文的内容，不重绘证据界面。

## 写作与校准

1. 先识别写给谁、作者想表达什么、有哪些事实依据。提炼口述里的主张和理由，再组织文章，避免逐句换词。缺少会改变事实或个人立场的信息时，提出具体问题，并继续能独立完成的部分。
2. 初次写作或用户要求风格校准时，读取 [表达示例](references/voice-examples.md)。理解语气、信息密度和判断的展开，不照搬主题、经历或句式。用户指定某篇原文时，读取全文；摘要不能冒充原文。
3. 去 AI 味先处理空泛和重复，再处理表达。保留有效句子，做能解决问题的最小修改；若整段只在宣布“接下来讲什么”，重新判断是否需要这一段。不为自然感虚构感官细节、情绪或经历，也不硬塞自嘲、脏话、跑题和故意含混；素材里已有的吐槽、情绪与不那么工整的口语要保留，不能把事实准确误解为全篇冷静无感。
4. 连着默读开头和整段，检查主语、指代、前后关系与信息推进。去掉套话后，读者仍应知道事情的背景、规则的对象和作者选择的理由。
5. 核对事实、作者立场、结构与公开范围是否仍完整，配图是否真正支持紧邻的结论。交付可读的正文，不把自检记录、AI 味评分或修改计数塞进文章；用户需要时再简述关键修改。

## 协作与维护

- 需要母稿管理、渠道适配或发布时，使用 [magic-creation](../magic-creation/SKILL.md)。单独润色不启动分发流程。
- 需要核对个人经历时，按任务范围读取获准使用的资料；读取权限不等于公开授权。
- 维护本 Skill 时合并用户明确的稳定偏好。选题事实、单篇素材和渠道机制留在对应文章或工作流；其他写作 Skill 的建议须与作者偏好、事实和当前用途相容。
